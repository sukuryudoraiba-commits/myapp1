## 1. コンセプト

**「自分だけのカードファイルを、スマホの中に作る」**

特定のカードゲームに限定せず、トレカ・ブロマイド・シールなど「番号のついた集めるもの」を整理する**汎用の整理ツール**。
実物のバインダーの感覚で、表紙・背景・アイコンを自分で作って飾れる。

アプリが提供するのは「空の入れ物と道具」だけ。中身（カードの情報・写真）はすべて利用者が自分で入れ、自分の端末の中に置く。

## 2. 権利配慮の設計原則

機能を足すときは、必ずこの5原則に照らして判定する。

| # | 原則 | 理由 |
| --- | --- | --- |
| P1 | **他人の著作物をアプリに同梱・配信しない** | カード画像・ロゴ・キャラクター絵は著作物。同梱や配信は複製権・公衆送信権の問題になる |
| P2 | **利用者の画像は端末の外に出さない** | 自分のカードを撮って自分で見るのは私的使用の範囲（著作権法30条）に収まりやすいが、サーバーへの保存や他人との共有は範囲を超える |
| P3 | **ネット上の画像・文章を取得も埋め込み表示もしない** | 自動収集は複製・利用規約違反。埋め込み表示（直リンク）も、表示のされ方によって著作者人格権の問題が指摘された例がある。**通常のリンクを開くだけ**にする |
| P4 | **扱うカード情報は「事実」だけ** | 番号・名称・レアリティなどは事実情報。一方、説明文・フレーバーテキスト・歌詞は著作物になりうるので扱わない |
| P5 | **作品名・ロゴ・公式を思わせる見た目を使わない** | アプリ名・アイコン・ストア説明・広告での作品名使用は、商標権や不正競争防止法の問題になる |

## 3. 権利リスクと設計上の対応

| 対象 | リスク | 設計上の対応 |
| --- | --- | --- |
| **カード画像（公式）** | 著作権（複製・公衆送信） | 同梱しない。取得しない。埋め込み表示しない（P1・P3） |
| **利用者が撮ったカード写真** | 端末内なら私的使用の範囲。外に出ると公衆送信 | 端末内（IndexedDB）にのみ保存。共有ファイル・共有用画像に含めない。サーバー同期は作らない（P2） |
| **未所持カードの見た目** | 画像を使うと上記と同じ | **番号＋名前の空きポケット**で表示。画像なし |
| **「ネットで調べる」** | ― | 番号と名前で検索ページを**新しいタブで開くだけ**。結果を取得・表示・保存しない |
| **参考ページのリンク** | 埋め込みは避けたい | URLを文字として保存し、タップで外部ブラウザを開くだけ。プレビュー画像（OGP）も取得しない |
| **カードリスト（番号・名前）** | 個々は事実だが、他人が整理したリストの丸ごと複製は、データベースの著作物（12条の2）や、作成者の労力へのただ乗りとして問題になりうる。サイトの利用規約にも注意 | アプリは**自動取得しない**。利用者が自分で入力・貼り付け。取り込み画面に注意書きと**出典欄**。公式カタログの同梱・配布サーバーは作らない |
| **カタログの共有** | 上記リストの再配布、画像の流出 | 共有ファイルは **番号・名前・レアリティ・タグのみ**。写真・メモ・参考リンク・ユーザー画像は含めない。共有時に「自分で作成したリストですか」の確認を出す |
| **説明文・フレーバーテキスト** | 著作物 | 入力欄を作らない。取り込み時、1項目が長い（40字超）行は警告して除外。メモ欄は自分用で共有対象外 |
| **表紙・アイコンの素材** | 既存キャラクター・ロゴに似た素材を同梱すると著作権・商標の問題 | 同梱素材は**自作の図形・柄・色のみ**。絵文字は端末のフォントで表示（絵文字画像を同梱しない） |
| **利用者がアップした表紙・アイコン画像** | 他人の画像を使う場合がある | 端末内のみ・共有対象外。選択時に「この端末の中だけで使われます」と表示（P2） |
| **アプリ名・アイコン・説明文** | 商標権、不正競争防止法（周知な表示との混同） | 作品名・シリーズ名・略称・ロゴを使わない。「◯◯対応」「◯◯公式」等も書かない。検索キーワードにも入れない |
| **画面デザイン** | 公式アプリ・公式グッズとの混同 | 独自のデザインにする。特定作品の配色・意匠を再現しない。プリセットのテンプレートに作品名を付けない |
| **バインダーの共有用画像** | カード写真を含むと公衆送信を助長 | 共有用画像を作る場合は **写真なし版**（番号・名前・所持マークのみ）に限る |
| **交換リストのテキスト** | ― | 番号と名前の文字だけなので問題になりにくい。現行のまま |
| **フォント・ライブラリ** | ライセンス違反 | 端末標準フォントを使う。外部ライブラリを入れる際はライセンスを確認し、README に記載 |
| **収益化（広告・有料化）** | 営利になると権利者の目が厳しくなり、「私的」の説明も弱くなる | 当面は無料・広告なし。収益化する前に専門家へ確認 |

### やらないことリスト（将来も含めて）
- ❌ 公式サイト・通販サイト・wiki などからの画像や情報の**自動取得**（スクレイピング）
- ❌ ネット上の画像の**埋め込み表示**（URLを指定して表示する機能を含む）
- ❌ 特定作品の**カタログ・画像・ロゴの同梱**や、運営者による配布
- ❌ カード写真の**サーバー保存・クラウド同期・利用者間の共有**
- ❌ カード画像を学習・照合に使う**画像認識**（公式画像の収集が前提になるため）
- ❌ アプリ名・説明・広告での**作品名の使用**

### 条件付きで検討できること
- 権利者が公開しているAPIや、利用許諾を得たデータの取り込み（許諾条件を確認できた場合のみ）
- カード番号の文字読み取り（自分の写真を端末内で処理するだけのもの）

## 4. 用語

| 用語 | 意味 |
| --- | --- |
| **フォルダ** | 利用者が作るバインダー。表紙・背景・アイコン・ポケット数を持つ |
| **ページ / ポケット** | フォルダの中の1ページと、カードを1枚入れる枠 |
| **カタログ** | あるシリーズのカードリスト（番号・名前・レアリティ）。利用者が自分で作る |
| **カード（定義）** | カタログの1行。持っていないカードもここに存在する |
| **所持データ** | 自分が持っている枚数・自分で撮った写真・メモ（端末内のみ） |

「カードの定義（事実情報・共有できる）」と「所持データ（個人のもの・共有しない）」を分ける。
これがコンプ率の自動計算と、権利面の線引き（共有してよいもの／いけないもの）の両方の土台になる。

## 5. 画面構成

```
フォルダ棚（ホーム）
├─ フォルダ作成・編集 …… 名前 / アイコン / 表紙・背景 / ポケット数
├─ フォルダの中（バインダー表示）
│   ├─ ポケットをタップ → カード詳細
│   │     ├─ 持っている：自分の写真・枚数・メモ
│   │     └─ 持っていない：番号・名前・「ネットで調べる」・参考ページのリンク
│   └─ ページ送り / 絞り込み（すべて・未所持・ダブり）
├─ カタログ
│   ├─ 作成：番号ルール（標準）／リストの貼り付け・CSV・共有ファイル（補助）
│   └─ 手入力・編集 / 共有ファイルの書き出し（文字情報のみ）
├─ 欲しい / ダブり（テキストでコピー）
└─ 設定（バックアップ・復元、権利について、問い合わせ先）
```

### 5.1 フォルダ棚（ホーム）
作ったフォルダが本棚のように並ぶ。表紙には設定した背景とアイコン、コンプ率。

### 5.2 フォルダ作成・編集
| 項目 | 選択肢 |
| --- | --- |
| 名前 | 自由入力 |
| アイコン | ① 絵文字 ② **スタンプ作成**（形・色・文字1〜2字）③ 自分の画像（端末内のみ） |
| 表紙・背景 | ① 単色 ② グラデーション ③ 柄（自作の幾何学柄）④ 自分の画像（端末内のみ） |
| ポケット数 | 1ページ 9 / 4 / 2 / 1 |
| 中身 | カタログ順に自動配置 ／ 自由に配置 |

### 5.3 フォルダの中（バインダー表示）
- **持っているカード**：自分の写真（なければレアリティ色＋名前）
- **持っていないカード**：**番号と名前だけの空きポケット**（画像は使わない）
- コンプ率バー、「未所持だけ」「ダブり」の絞り込み、スワイプでページ送り。

### 5.4 カード詳細
- 持っている：写真の撮影・変更、枚数、メモ、交換に出す。
- 持っていない：番号・名前・レアリティ、**「🔍 ネットで調べる」**（検索を新しいタブで開く）、
  **参考ページのリンク**（登録したURLを外部ブラウザで開く）、「欲しいに入れる」「手に入れた！」。

### 5.5 カタログ作成（番号ルール）★標準

カードの番号は「通常の弾」と「プロモーション（付録・配布・グッズ付属など）」で体系が違うことが多い。
そこで、**番号の付け方（ルール）を利用者が登録**し、空きポケットをまとめて作れるようにする。

| 設定項目 | 例 | 説明 |
| --- | --- | --- |
| 頭の文字 | `S2` / `PX` / なし | 弾や入手方法を表す記号。8字まで |
| 区切り | `-` / 空白 / なし | 頭の文字と番号の間 |
| 桁数 | `01` / `001` | 0で埋める桁数（1〜4） |
| はじめ〜おわり | 1 〜 60 | 1ルール500枚まで |
| 意味・グループ名 | 「第2弾（通常）」「おかし付属」 | 任意。20字まで |

- 1つのカタログに**複数のルール**を持てる（例：通常60枚＋プロモ12枚）。
- 入力中に「S2-01、S2-02、… S2-60（60枚）」のようにプレビューを出す。番号が重なるルールは追加できない。
- ルールは次の3つに使う。
  1. **一括作成**：範囲の番号で空きポケットを作る（名前は空欄。あとから入力できる）
  2. **自動分類**：カードを1枚ずつ登録するとき、番号の頭の文字からグループを判定する
  3. **並び順・絞り込み**：バインダーや一覧で、ルール（グループ）ごとに並べる・絞り込む
- 上級者向けに、`16 04-##` のように `#` を番号に置き換える**書式の直接入力**も用意する（空白を含む番号や、頭の文字が複数に分かれる体系に対応するため）。

**権利面の扱い**
- 番号の付け方そのものは事実・規則であり、著作物ではない。利用者が自分で登録する分には問題になりにくい。
- ただし、アプリが特定作品のルール一式（記号と意味の対応表など）を**プリセットとして同梱すると、作品名を扱うことになり P5 に触れる**。同梱しない。
- ルールは共有ファイルに含めてよい（記号・桁数・範囲・利用者が付けたグループ名のみ）。

### 5.6 カタログ取り込み（リストの貼り付け）※補助
- 利用者がリストを貼り付け →「番号, 名前, レアリティ」を自動判別 → プレビュー → 確定。
- 取り込むのは **番号・名前・レアリティ・短いタグ** のみ。長文の項目は除外。
- **出典欄**（任意）と、次の注意書きを常に表示：
  > 取り込むのは番号や名前などの情報だけにしてください。他のサイトのリストを使うときは、そのサイトの利用規約を確認し、個人で使う範囲にとどめてください。

### 5.7 設定「権利について」
- 非公式の整理ツールであり、いかなる作品・企業とも関係がないこと。
- データと写真は端末内にのみ保存されること。
- 利用者が登録する内容は利用者の責任で、私的な利用の範囲にとどめること。
- 権利者からの連絡を受け付ける**問い合わせ先**（公開前に用意する）。

## 6. データ設計（IndexedDB）

`共有` 列は、共有ファイル（カタログ書き出し）に含めるかどうか。バックアップ（本人用の全データ書き出し）は別物で、本人の端末間の移行に使う。

```ts
Folder {                        // 共有: ×
  id, name, order,
  icon:  { type: 'emoji' | 'stamp' | 'image', value, shape?, color?, text? },
  cover: { type: 'color' | 'gradient' | 'pattern' | 'image', value, pattern?, colors? },
  pocketsPerPage: 1 | 2 | 4 | 9,
  catalogIds: string[],
  layout?: (cardId | null)[],
}

Catalog {                       // 共有: ○（name, tags の定義, rules のみ）
  id, name,
  rules: NumberRule[],          // 番号ルール（利用者が登録）
  tagNames: string[],           // 独自の短い項目名（例：['種類','色']）
  source?: string,              // 出典メモ（共有: ×）
}

NumberRule {                    // 共有: ○
  id,
  label: string,                // 意味・グループ名。20字まで
  prefix: string,               // 頭の文字。8字まで
  sep: string,                  // 区切り。2字まで
  digits: 1 | 2 | 3 | 4,        // 0埋めの桁数
  from: number, to: number,     // 範囲（1ルール500枚まで）
  format?: string,              // 上級者向けの書式（例 '16 04-##'）。指定時は prefix/sep/digits より優先
}

CardDef {                       // 共有: ○（事実情報のみ）
  id, catalogId,
  ruleId?: string,              // どのルールで作られたか／どのルールに分類されたか
  no: string,                   // 12字まで
  name: string,                 // 40字まで。ルールで一括作成した直後は空欄
  rarity: string,               // 12字まで
  tags: Record<string,string>,  // 各20字まで
  refPageUrl?: string,          // 参考ページ（開くだけ。共有: ×）
}

Owned {                         // 共有: ×（すべて個人のデータ）
  cardId, qty, wish, trade,
  photo?: Blob,                 // 自分で撮った写真
  memo?: string,
}

Asset { id, blob, kind: 'icon' | 'cover' }   // 利用者の画像。共有: ×
```

- 画像URLを持つ項目は**存在しない**（v0.2 の `refImageUrl` は削除）。
- 文字数の上限は、説明文などの長文が入り込むのを防ぐためのもの。
- v0.1 の「弾」は Catalog に、「カード」は CardDef＋Owned に自動変換する。

### 通信について
アプリは外部サーバーと一切通信しない（アプリ本体の読み込みを除く）。
外部へ出るのは、利用者が「ネットで調べる」「参考ページを開く」を押して**別タブでブラウザが開く**ときだけ。

## 7. 開発ステップ

| # | 内容 | 権利面のチェック |
| --- | --- | --- |
| 1 | GitHub Pages で公開（v0.1 とモック） | サンプル名は架空のもの。作品名なし |

| 7 | カタログ共有（文字情報のみ） | 写真・メモ・リンクが含まれないことをテストで確認 |

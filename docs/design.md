# カードクローゼット 設計書 v0.2（汎用カードフォルダ版）

> モック: [`mock/index.html`](../mock/index.html)（GitHub Pages では `/mock/`）

## 1. コンセプト

**「自分だけのカードファイルを、スマホの中に作る」**

特定のカードゲームに限定せず、トレカ・ブロマイド・シールなど「番号のついた集めるもの」なら何でも整理できるアプリにする。
実物のバインダー（ポケットファイル）の感覚を大事にし、表紙や背景を自由に飾れる。

| v0.1（現在のプロトタイプ） | v0.2（この設計） |
| --- | --- |
| 「弾」とカードの一覧 | **フォルダ（バインダー）** にポケット形式で収納 |
| 部位・ブランドなど項目が固定 | 項目は **タグ / 自由項目** で汎用化 |
| 未所持カードは手で登録 | **カタログ（カードリスト）** を取り込み、未所持は番号やネットの情報で表示 |
| 見た目は固定 | 表紙・背景・アイコンを **自由に作成** |

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| **フォルダ** | ユーザーが作るバインダー。表紙・背景・アイコン・ポケット数を持つ |
| **ページ / ポケット** | フォルダの中の1ページと、カードを1枚入れる枠（3×3 など） |
| **カタログ** | あるシリーズ・弾のカードリスト（番号・名前・レアリティなど）。所持していないカードもここにある |
| **カード（定義）** | カタログの1行。「No.01 ○○」という“カードの種類” |
| **所持データ** | 自分が持っている枚数・自分で撮った写真・メモ |

ポイントは **「カードの定義（カタログ）」と「自分の所持状況」を分ける** こと。
これにより、持っていないカードも番号付きで空きポケットに表示でき、コンプ率が自動で出る。

## 3. 画面構成

```
フォルダ棚（ホーム）
├─ フォルダ作成・編集 …… 名前 / アイコン / 表紙・背景 / ポケット数
├─ フォルダの中（バインダー表示）
│   ├─ ポケットをタップ → カード詳細
│   │     ├─ 持っている：写真・枚数・メモ
│   │     └─ 持っていない：番号・名前・参考画像・「ネットで調べる」
│   └─ ページ送り / 一覧表示切替 / 絞り込み
├─ カタログ
│   ├─ 取り込み（テキスト貼り付け / CSV / 共有ファイル）
│   └─ 手入力・編集
├─ 欲しい / ダブり（v0.1 から継続）
└─ 設定（バックアップ・復元）
```

### 3.1 フォルダ棚（ホーム）
- 作ったフォルダが本棚のように並ぶ。表紙には設定した背景とアイコン、コンプ率。
- 長押しで並び替え、「＋」で新規作成。

### 3.2 フォルダ作成・編集
| 項目 | 選択肢 |
| --- | --- |
| 名前 | 自由入力 |
| アイコン | ① 絵文字から選ぶ ② **スタンプ作成**（形：丸/星/ハート/リボン、色、中の文字1〜2字）③ 自分の画像 |
| 表紙・背景 | ① 単色 ② グラデーション ③ 柄（ドット/ストライプ/チェック/星）④ 自分の画像 |
| ポケット数 | 1ページ 9 / 4 / 2 / 1 ポケット（実物のファイルに合わせる） |
| 中身 | カタログを紐付け（自動で番号順に並ぶ）／ 自由に配置 |

変更はすぐ上部のプレビューに反映する。

### 3.3 フォルダの中（バインダー表示）
- 背景の上に、ポケットが並ぶページを表示。左右スワイプでページ送り。
- **持っているカード**：自分の写真（なければカード色＋名前）
- **持っていないカード**：
  1. 参考画像を登録してあれば **薄く・グレーで** 表示し「未所持」マーク
  2. なければ **カード番号と名前だけの空きポケット**
- 上部にコンプ率バー。「未所持だけ表示」切替。

### 3.4 カード詳細
- 持っている：写真の撮影/変更、枚数（＋/−）、状態、メモ、欲しい/交換に出す。
- 持っていない：番号・名前・レアリティ・参考画像、**「🔍 ネットで調べる」**（番号＋名前で検索を開く）、「欲しいに入れる」「手に入れた！」。

### 3.5 カタログ取り込み
ネットで公開されているカードリストを、利用者がコピーして貼り付ける方式を基本とする。

```
01, ピンクリボンブラウス, PR
02, スターライトスカート, R
03, ハートブーツ, N
```
- 「番号, 名前, レアリティ」程度の簡単な形式を自動判別し、プレビュー→確定。
- CSV ファイル、アプリで書き出したカタログ（JSON）の読み込みにも対応。
- 作ったカタログは JSON で書き出して友だちと共有できる。

## 4. 「持っていないカード」の情報をどう参照するか

| 方式 | 内容 | 判断 |
| --- | --- | --- |
| A. 番号と名前だけで表示 | カタログのテキスト情報のみ | ✅ **基本**。必ず使える |
| B. 「ネットで調べる」ボタン | 番号＋名前で検索ページを開く。画像は保存しない | ✅ **採用**。権利面で安全、実装も簡単 |
| C. 参考画像URLを登録 | 利用者が画像のURLを貼ると、それを表示する（端末に保存しない） | △ **任意機能**。リンク切れや表示不可が起きる。公式画像の扱いに注意書きを出す |
| D. アプリが自動で画像を集める | サーバーで公式サイト等から取得 | ❌ **やらない**。利用規約・著作権の問題、サイト変更で壊れる |

→ **A＋B を標準、C をオプション**とする。将来、権利者の許可を得たデータや公開APIがあるゲームに限り、取り込み元として追加を検討する。

## 5. データ設計（IndexedDB）

```ts
Folder {
  id, name, order,
  icon:  { type: 'emoji' | 'stamp' | 'image', value, shape?, color?, text? },
  cover: { type: 'color' | 'gradient' | 'pattern' | 'image', value, pattern?, colors? },
  pocketsPerPage: 1 | 2 | 4 | 9,
  catalogIds: string[],        // 紐付けたカタログ（番号順に自動配置）
  layout?: (cardId | null)[],  // 自由配置モードのときの並び
  createdAt, updatedAt
}

Catalog {                       // シリーズ / 弾
  id, name, category,           // category: 自由入力（例：アイドルカード、スポーツ）
  fields: string[],             // このカタログ独自の項目名（例：['ブランド','部位']）
  source?: string,              // 情報の出典メモ
  createdAt
}

CardDef {                       // カードの種類（所持していなくても存在）
  id, catalogId, no, name, rarity,
  attrs: Record<string,string>, // fields に対応する値
  refImageUrl?: string,         // 参考画像URL（保存しない）
  refPageUrl?: string           // 参考ページ
}

Owned {                         // 自分の所持状況（CardDef と 1:1）
  cardId, qty, wish, trade,
  photo?: Blob,                 // 自分で撮った写真（縮小して保存）
  memo?, updatedAt
}

Asset { id, blob, kind: 'icon' | 'cover' }   // ユーザーがアップした画像
```

- 画像は Blob で別ストアに保存（v0.1 の dataURL より容量効率が良い）。
- v0.1 の「弾」は Catalog に、「カード」は CardDef＋Owned に移行する。初回起動時に自動変換。

## 7. 注意事項
- 非公式ツールであることを明記し、公式の画像・ロゴは同梱しない。
- 参考画像URL機能では「権利者のサイトの画像を表示する場合は、各サイトの規約に従ってください」と表示する。
- データは端末内のみ。機種変更に備えてバックアップを促す。
